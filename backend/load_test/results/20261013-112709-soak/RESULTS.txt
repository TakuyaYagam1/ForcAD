Interpretation
The immediate source of 503s was the API admission gate with all 256 slots occupied.
Increased pgx waits and severe Windows memory pressure during the largest episode are confirmed.
The root cause of all four episodes has not been established. These correlations do not identify PostgreSQL,
GC or WSL as the sole cause; the rare pauses require a separate reproduction.
The next comparison should prioritize controlling physical memory across the entire Windows/WSL host
and repeating the same workload without memory pressure, keeping application limits unchanged for comparison.
